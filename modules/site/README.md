# Lotline foundation

The homepage introduces Lotline for the dealership its profile names (fictional Ridgeway Motors until an admin renames it, #23). It describes the forthcoming dealership operations app and links to the existing database health API. Staff sign in through the `staff` module, keep the lot through the `inventory` module, the customers through the `customers` module and the sales through the `sales` module; signed-in staff land on the `dashboard` module's page at `/app`.

`BootstrapPage` puts the theme's `TopBar` in the `header` region and its `BootstrapIntro` in `content`, through `PageDocuments`, titled `Dashboard · Lotline` after its heading and the signed-out sidebar's link to it. Its health link carries `data-enhance="off"`, since `/health` answers JSON, which Tessera cannot swap in: a click loads it as a document. Two blocks fill the rest of the drawer on every page: `NavigationBlock` places the sidebar (the site's name, then a link per area with its Heroicon, the current one marked from the request path; areas join as their pages land, and Inventory, Customers, Sales, Leads and Holds (#20, its clock icon) show only when `StaffSession`, which `site` requires `staff` for, holds a signed-in member, Reports (#21, its chart-bar icon) only when that member is an admin or a sales manager, who read the reports, and Settings (#22, the cog) and Jobs (#35, its queue-list icon, AIC's queue at `/app/jobs`) only when they are an admin, the role staff's `StaffStanding` keeps current in the session; for that member Dashboard goes to the dashboard at `/app` (#8), current on `/app` alone since every staff page sits under it, and otherwise to `/`) and `SiteFooterBlock` the footer line, naming the dealership through staff's `StaffDealership`. The footer is an AIC `SourcedComponent` over `FooterPart`, so the name is read only when the page renders the footer (#25), never for a Tessera answer that leaves it out. The `header` region is a row: the page's `TopBar`, then the `staff` module's `AccountMenuBlock`. The components live in `themes/lotline/`: each template in `components/<Name>/`, each class in `src/Components/<Name>/`.

`ThemeGuidePage` answers `/theme`, the style guide, from `ThemeSamples`, which composes the sample services: charts, records (the list honours `q`, `status`, `sort` and `page`), filters, stock, forms, actions and parts. `ThemeGuidePost` checks the sample vehicle form (`ThemeEntry`) and answers 422 with each field's error, or 303 back to the guide (both pages are titled `Theme · Lotline`); the delete and sign-out samples go back too. Nothing is stored. The sample account menu passes its own id stem, `sample-account`, and its own form ids, so `/theme` signed in holds each id once beside the header's menu. `ThemeEntry::problems()` avoids `array_intersect_key` until the compiler carries AIC #165.

The guide's Resilience panel (#34) links to six case pages under `/theme/resilience/`, one for each failure Tessera handles, so a reviewer can trigger it on purpose; nothing outside the guide links to them. Each is a small Page in `ResilienceCases`' frame (the paths, the guide's links, the top bar, a line saying what the case shows, the case in a panel, a link back to `/theme`). The refused, protocol and full-visit cases are `ResilienceSamples`'; the three that count an event go through `ResilienceWatches`, whose theme `CaseWatch` listens for that event and counts it in a signal of its own. `tessera:expired` and `tessera:indeterminate` are left to Tessera, so its reload prompt and its "it may have been saved" alert show; `tessera:error` is counted and cancelled, so the console stays clean.

- `expired`: "Expire the token" renews the session's form token and answers 204, which carries no token, so the page keeps one the session no longer holds; "Send" then gets the form guard's 419 (403 with JavaScript off).
- `gateway`: its form posts to a path with no POST route. `ResilienceFaults`, the module's middleware after the session, answers every POST there as a gateway does after its own timeout, 504 in plain text, at once. Tessera cannot use that answer to a write, so it reports the write indeterminate. Nothing holds a worker open.
- `refused`: the guide's vehicle form (`ThemeSampleForms::vehicle()` takes its action, and `posted()` reads it for both posts) posting to the case: 422 with three errors and AIC's `Alert`, which carries `data-error-summary`, or 303 back.
- `feed`: a `FeedStatus` line polled every second from its own page. "Take the feed down" starts an outage in the session (`ResilienceOutage`: `site.feed.down` and `site.feed.failed`); `ResilienceFaults` answers the next three polls 503 in plain text, and the fourth answers again.
- `protocol`: `ResilienceFaults` answers every Tessera request to the page 400 with `Tessera-Protocol: 1`, as a server that speaks only protocol 1 does, so Tessera loads it whole; a plain request gets the page.
- `full-visit`: its form answers AIC's `PageFullVisit` to the page.

A redirect off the site is not among them: `PageRedirect` and `PageFullVisit` take only a path on this site (AIC #207).

The framework serves `/assets/aic.css` (the bundled theme stylesheet), the pinned Tessera script and its map from `build/assets/`, with byte ranges, before the application is assembled. The native comparison steps cover health, a missing route, the homepage, those files, missing and traversal asset requests and a stylesheet range, and every resilience case, its faults included.

The site has no brand icon yet: browser requests for `/favicon.ico` return 404.
